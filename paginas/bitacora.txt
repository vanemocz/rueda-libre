# Elecciones tipo de datos del formulario Rueda libre

    * Tipo email para el correo electrónico:
        Se eligió el tipo de dato email porque permite validar que el correo ingresado tenga una estructura básica válida. Esto ayuda a reducir errores al momento de registrar la información de contacto del cliente y facilita el uso de las validaciones nativas de HTML.
    * Tipo date para la fecha del alquiler
        Se eligió el tipo de dato date porque permite al usuario seleccionar una fecha mediante un calendario, facilitando su ingreso y disminuyendo errores de digitación. Además, los atributos min y max permiten establecer el rango de fechas autorizado para realizar las reservas, según las reglas del negocio.
    * Tipo number para la cantidad de bicicletas
        Se eligió el tipo de dato number porque la cantidad de bicicletas debe representarse mediante un valor numérico. Este tipo permite establecer límites mínimos y máximos mediante los atributos min y max, garantizando que la cantidad solicitada esté entre 1 y 6 bicicletas.

# Prueba de herencia

    Prueba 1. Propiedad heredada: `font-family`

    Se inspeccionó un elemento de la página mediante DevTools y se comprobó que recibe la propiedad `font-family` declarada en `body`. La fuente general se establece mediante la variable `--fuente-textos`, cuyo valor es Open Sans.

        **Resultado:** se comprueba la herencia de la tipografía desde el elemento `body`.

    Prueba 2. Propiedad no heredada: `background-color`

    Se identificó que `background-color` está declarado en `body` mediante la variable `--color-fondo`. Esta propiedad no se hereda automáticamente a los elementos descendientes.

        **Resultado:** el fondo Crema se aplica a `body`, pero los elementos internos no reciben automáticamente esa propiedad por herencia.

# Prueba Fuente específica para los encabezados

    Se inspeccionó el elemento `<h2>` mediante DevTools y, en la pestaña Computed, se comprobó que utiliza la fuente Montserrat con un grosor de 700. Esta configuración proviene del selector agrupado de encabezados definido en la hoja de estilos externa.

        **Resultado:** se verifica que los encabezados utilizan la tipografía establecida en la identidad visual de Rueda Libre, mientras que los párrafos utilizan Open Sans, definida en `body`.

# Prueba de especificidad CSS

    Se observó que la declaración `color` del selector `.activo` aparece tachada, mientras que la declaración `color` del selector `#menu a` permanece activa.

    El selector `#menu a` tiene una especificidad de `(1, 0, 1)`, mientras que `.activo` tiene una especificidad de `(0, 1, 0)`. Por esta razón, el navegador aplica el color de `#menu a`.

    La propiedad `font-weight: 600` de `.activo` sí se aplica porque no existe un conflicto para esa propiedad entre estas dos reglas.

# La flota en cuadrícula: CSS Grid y Flexbox

    * Pruebas de adaptabilidad

    Se realizaron pruebas utilizando el modo dispositivo de las herramientas de desarrollador del navegador (DevTools).

    Los resultados observados fueron:

    | Ancho de pantalla | Columnas observadas |
    | 1280 px | 4 |
    | 900 px | 3 |
    | 500 px | 2 |

    Los resultados demuestran que la cuadrícula reorganiza automáticamente las bicicletas según el espacio disponible, sin necesidad de establecer media queries para modificar la cantidad de columnas.

    * Justificación técnica

    Se eligió CSS Grid para organizar la flota porque permite distribuir elementos en dos dimensiones, filas y columnas, y adaptar su distribución al espacio disponible.

    Por otra parte, se utilizó Flexbox dentro de cada tarjeta porque los elementos tienen una distribución principalmente vertical. La propiedad `margin-top: auto` permite que los enlaces de reserva permanezcan al final de las tarjetas, incluso cuando las descripciones tienen diferentes longitudes.

    La combinación de ambas tecnologías permite mantener una presentación organizada, uniforme y adaptable.

# CSS Grid o Flexbox

    1. Portada - CSS Grid

    Se utilizó Grid para organizar la sección principal de la portada en dos columnas: una para el contenido textual y otra para la imagen. Se eligió esta herramienta porque permite controlar la distribución en dos dimensiones y establecer proporciones mediante unidades fr.
    Grid

    2. Galería de rutas – CSS Grid

    Se utilizó Grid para distribuir las tres tarjetas de recorridos en una fila, manteniendo una separación uniforme entre ellas. Esta herramienta facilita la organización de varias tarjetas en filas y columnas, permitiendo adaptar su distribución según el espacio disponible.
    Grid

    3. Página de reservas – CSS Grid

    Se utilizó Grid para distribuir el formulario y la información de contacto en una proporción 2:1. El formulario ocupa dos fracciones del espacio disponible y la información de contacto una fracción. Se eligió Grid porque permite establecer una distribución precisa entre dos áreas independientes.
    Grid

    4. Fila de campos del formulario – Flexbox

    Se utilizó Flexbox para ubicar los campos de tipo de documento y número de documento en una misma fila. Se eligió esta herramienta porque permite organizar elementos en una sola dimensión, distribuir el espacio disponible y controlar la separación entre ellos. 

    5. Encabezado – Flexbox

    Se utilizó Flexbox para distribuir horizontalmente el nombre de la marca y el menú de navegación. 

    6. Pie de página – Flexbox

    Se utilizó Flexbox para organizar horizontalmente los elementos del pie de página: derechos de autor, correo electrónico y año. 

# Diseño responsive – Versión 1.5

    Problemas encontrados y soluciones

        Formulario de reservas: En móviles se dividía en dos columnas. Se ajustó con CSS Grid para mostrar una columna y activar dos columnas desde 678 px.

        Tablas de tarifas: El contenido ocupaba demasiado espacio. Se redujo el relleno de las celdas y el tamaño de la letra para evitar el desplazamiento horizontal.

        Imágenes: Algunas podían superar el ancho de su contenedor. Se aplicó max-width: 100% y height: auto para adaptarlas a diferentes pantallas.

    Pruebas realizadas

        Se verificó el sitio mediante DevTools en las siguientes resoluciones:

        360 px: visualización móvil correcta.

        768 px: distribución para tablet correcta.

        1280 px: visualización de escritorio correcta.
